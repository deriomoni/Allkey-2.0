# Резервное копирование БД allkey — установка

Готовые файлы в репозитории (**сами по себе ничего не делают**, ставятся на сервере вручную):

- `pg_backup.sh` — скрипт: сжатый дамп PostgreSQL → проверка → выгрузка во внешнее хранилище → ротация;
- `pg_backup.cron` — готовая cron-запись (ежедневно в 02:30);
- `RESTORE-BACKUP.md` — пошаговое восстановление из дампа (для не-разработчика).

Всё это выполняется **на сервере** и требует SSH/консольного доступа. У кого нет доступа —
передайте задачу тому, кто настраивал сервер.

---

## Почему нельзя хранить копии только на сервере

Если дамп лежит на том же диске, что и база, — это не резервная копия. Сгорит диск,
удалят сервер, зашифрует вымогатель — пропадёт и база, и «бэкап» разом. Поэтому копии
**обязательно** уезжают во внешнее хранилище. Локально скрипт держит их лишь несколько
дней как перевалочный буфер.

## Куда выгружать (внешнее хранилище)

Рекомендация по порядку предпочтения:

1. **Объектное хранилище PS.KZ (S3-совместимое)** — тот же провайдер, что и домен, оплата и
   поддержка в одном месте. Создайте бакет (например `allkey-backup`) и ключ доступа.
2. **Любое S3-совместимое** (Backblaze B2, Selectel, VK Cloud, AWS S3) — если нужен провайдер
   вне PS.KZ (полезно: копия не у того же поставщика, что и сервер).
3. **Отдельный сервер/NAS по SFTP** — если объектного хранилища нет.

Подключение — через `rclone` (умеет и S3, и SFTP, одинаковый синтаксис для скрипта).

## Установка на сервере (один раз)

Ниже `/opt/allkey` — папка, куда склонирован репозиторий (там лежит `docker-compose.prod.yml`
и `.env`). Подставьте свой путь.

### 1. Скопировать скрипт и дать права

```bash
sudo cp /opt/allkey/pg_backup.sh /opt/allkey/pg_backup.sh   # уже в репозитории; шаг для наглядности
sudo chmod 700 /opt/allkey/pg_backup.sh
sudo mkdir -p /var/backups/allkey                            # временная локальная папка
```

### 2. Установить и настроить rclone (внешнее хранилище)

```bash
sudo apt-get update && sudo apt-get install -y rclone
sudo rclone config
```

В интерактивном мастере создайте remote с именем **`allkey-backup`**:
- для S3/PS.KZ: тип `s3`, provider `Other`, введите `access_key_id`, `secret_access_key`,
  `endpoint` (адрес хранилища PS.KZ), регион при необходимости;
- для SFTP: тип `sftp`, хост, пользователь, ключ.

Проверьте, что remote работает и бакет доступен:

```bash
sudo rclone lsd allkey-backup:
```

> В `pg_backup.sh` по умолчанию выгрузка идёт в `allkey-backup:allkey/db`. Другое имя/путь —
> поменяйте переменную `RCLONE_REMOTE` в скрипте или задайте `ALLKEY_BACKUP_REMOTE` в cron.

### 3. Разовый прогон вручную (проверка, что всё работает)

```bash
sudo /opt/allkey/pg_backup.sh
sudo rclone ls allkey-backup:allkey/db      # должен появиться свежий .sql.gz
```

Если скрипт ругается — читайте сообщение: чаще всего не найден `.env`, не тот путь к репозиторию
(`ALLKEY_DIR`), или не настроен rclone.

### 4. Поставить в cron

```bash
sudo cp /opt/allkey/pg_backup.cron /etc/cron.d/allkey-pg-backup
# ВАЖНО: откройте файл и поправьте путь к скрипту, если репозиторий не в /opt/allkey
sudo nano /etc/cron.d/allkey-pg-backup
sudo systemctl restart cron        # применить (в некоторых дистрибутивах: service cron reload)
```

Проверить, что задача видна:

```bash
cat /etc/cron.d/allkey-pg-backup
```

### 5. Проверять, что бэкапы идут

- Лог: `sudo tail -n 50 /var/log/allkey-backup.log` — там строки «Дамп готов…» и «Выгружено…».
- Хранилище: `sudo rclone ls allkey-backup:allkey/db` — файлы за последние дни.
- **Раз в месяц** делайте пробное восстановление на тестовой базе (см. `RESTORE-BACKUP.md`).
  Бэкап, из которого ни разу не восстанавливались, — это не бэкап, а надежда.

## Что настраивается в скрипте

| Переменная | По умолчанию | Значение |
|---|---|---|
| `ALLKEY_DIR` | папка скрипта | где лежат `docker-compose.prod.yml` и `.env` |
| `STAGING_DIR` | `/var/backups/allkey` | временная локальная папка |
| `KEEP_LOCAL_DAYS` | `7` | сколько дней держать копии локально |
| `RCLONE_REMOTE` | `allkey-backup:allkey/db` | адрес внешнего хранилища |
| `KEEP_REMOTE_DAYS` | `30` | сколько дней держать копии в хранилище |

Частота (ежедневно в 02:30) задаётся в `pg_backup.cron`. Хотите чаще или в другое время —
меняйте первую строку с расписанием там же.
