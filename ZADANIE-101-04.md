## Контекст

Мы добавляем на allkey.kz модуль «Помогайка по форме 101.04» — визард, который по ответам пользователя определяет обязательства налогового агента при выплатах нерезидентам и готовит данные для формы 101.04.

Вся налоговая логика **уже исследована и зафиксирована**. Твоя задача — перенести её в код, а не переизобретать.

**Первая версия — внутренняя бета:** доступ только сотрудникам и администратору, за feature flag. Внешним пользователям не показываем.

## Железные правила

Нарушение любого из них — блокер приёмки.

1. **Не придумывай налоговые нормы.** Всё, что нужно, есть в базе знаний и `rules.json`. Если для реализации не хватает нормы — **остановись и спроси**, не достраивай по аналогии и не ищи в интернете.

2. **Ставки, коды, списки стран, тексты подсказок и предупреждений живут в данных, а не в коде.** Обновление законодательства не должно требовать релиза. Хардкод любой ставки или кода в исходниках — блокер.

3. **Движок расчёта — чистая функция** вида `evaluate(answers, refbooks, asOfDate) → Verdict`. Без побочных эффектов, без обращений к сети, без вызовов LLM внутри расчёта. Один и тот же вход всегда даёт один и тот же выход.

4. **Никакой модели в пути расчёта.** Если позже добавим разбор документов или свободное описание ситуации — они только *предзаполняют ответы визарда*, а считает всегда детерминированный движок.

5. **Версионируй правила.** У каждого прохождения сохраняется `rules_version` и полный набор ответов, чтобы вывод можно было воспроизвести спустя год. Пересчитывать старые сессии при обновлении справочников запрещено.

6. **Дисклеймер обязателен** на экране результата и в любом экспорте. Текст — в ТЗ, §6, блок 7.

7. **Три уровня уверенности вывода:** `confirmed`, `likely`, `manual_review`. При `manual_review` показываем вопрос и что проверить, а не готовый ответ.

8. **Не трогай существующий функционал сайта.** Модуль изолирован. Если нужно менять общие компоненты, роутер или схему БД — сначала опиши, что и зачем, и дождись подтверждения.

## Фаза 3. Движок

Движок — на **Python, в `backend/app/f10104/`**, по образцу вычислительной части personnel. Фронтенд вызывает его через POST и не дублирует налоговую логику у себя: единственный источник истины — бэкенд.

Реализуй `evaluate()` строго по правилам из ТЗ, §5: группы `R-ROUTE`, `R-KPN`, `R-CONV`, `R-VAT`, `R-REP`, `R-RISK`, плюс новые правила `R-REP-08/09`, `R-FORM-01…05`, `R-KPN-19`, `R-VAT-10` из §8.

`Verdict` должен содержать: обязательство по КПН (облагаемость, ставка, сумма, основание), обязательство по НДС, периоды и сроки по обоим налогам отдельно, необходимость сдачи 101.04 и срок, заполненные значения граф приложения A–Y, значения строк 101.04.001–006, список сработавших флагов, нормативное обоснование по каждому шагу, `rules_version`.

**Помни про два разных периода:** для 101.04 период определяется по дате выплаты, для НДС — по дате совершения оборота. Они регулярно не совпадают, это не ошибка.

### Тесты движка — писать до UI

Кладём в `backend/app/f10104/tests/` и **расширяем `testpaths` в `pytest.ini`**, иначе они не будут запускаться. Обязательно повторить `test_gating.py` из personnel для проверки границы доступа.

Перенеси в юнит-тесты **все 20 тест-кейсов из ТЗ §7** и **весь контрольный набор из официального разбора построчного заполнения** (ТЗ §8, таблица из 10 нерезидентов).

## Фаза 4. Интерфейс

Визард по дереву вопросов из ТЗ §4: блоки S1, S2, S5, S3, S6, S7, S8, S4, S9 и экран результата. Порядок шагов важен — он подобран так, чтобы условные шаги не перескакивали при смене ответа.

Требования из ТЗ §10, самые важные:
- один вопрос на экран;
- подсказка рядом с вариантом ответа, а не в отдельной справке;
- **предупреждения появляются по ходу, а не только в конце** — это главная обучающая функция;
- промежуточный вывод между блоками («пока получается: КПН 20 %, форма за III квартал»);
- автосохранение черновика;
- экспорт результата в PDF или на печать с датой и версией правил.

Прототип `pomogayka-101-04.html` — рабочий референс **поведения и текстов**, а не оформления. Формулировки вопросов, подсказок и предупреждений бери оттуда дословно, они выверены. Тёмную тему прототипа **не копируй** — верстай в стиле существующих сверок, теми же компонентами и токенами.
