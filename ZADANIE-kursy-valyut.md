# Задание: модуль «Курсы валют НБ РК»

Дополнение к `ZADANIE-101-04.md`. Можно делать до помогайки или параллельно — помогайка от этого модуля зависит.

---

## Зачем

Две задачи сразу:

1. **Самостоятельный инструмент** — выбрать валюты и период, получить таблицу курсов, выгрузить в CSV или Excel. Аналог загрузки курсов в 1С.
2. **Сервис для помогайки 101.04** — она должна подставлять официальный курс на дату выплаты и на дату совершения оборота вместо ручного ввода. Сейчас пользователь вбивает курс руками, это лишний шаг и источник ошибок.

**Переиспользовать нечего — проверено.** Сверка курсов валют живёт не в вебе, а в отдельном desktop-приложении `AI-BUH/` на Tauri, и там курсы **парсятся из выгрузки, которую загружает сам пользователь** (`src/lib/currencyReconcile.ts`, функция `parseNbRates`). Клиента к API Нацбанка нет ни в одном из двух проектов. Историю курсов делаем с нуля.

---

## Источник данных

Национальный Банк РК отдаёт открытый XML без ключей и лимитов.

**За конкретную дату:**
```
GET https://nationalbank.kz/rss/get_rates.cfm?fdate=17.08.2026
```
```xml
<rates>
  <title>Official exchange rates of National Bank of Republic Kazakhstan</title>
  <date>17.08.2026</date>
  <item>
    <fullname>ДОЛЛАР США</fullname>
    <title>USD</title>
    <description>464.02</description>
    <quant>1</quant>
    <change>0.00</change>
  </item>
  …
</rates>
```

**Последние опубликованные:**
```
GET https://nationalbank.kz/rss/rates_all.xml
```
RSS 2.0, элементы `<item>` с `<title>`, `<pubDate>`, `<description>`, `<quant>`, `<index>`, `<change>`.

Оба эндпоинта проверены 17.08.2026, отдают около 49 валют. Публикация ежедневная, без пропусков на выходные и праздники — см. пункт 2 ниже.

---

## Четыре вещи, на которых легко ошибиться

**1. Курс указан за `quant` единиц.** Нормализованный курс за одну единицу = `description / quant`. Для японской иены, вона, сума и ряда других `quant` равен 10, 100 или 1000. Без деления получите курс, завышенный в сто раз. В хранилище кладите **нормализованный** курс, а `quant` сохраняйте для справки.

**2. Курс публикуется каждый календарный день — включая выходные и праздники.** *(Исправлено 19.08.2026. Прежняя редакция задания утверждала обратное — это была ошибка.)* Проверено прямыми запросами: суббота 13.06.2026 — 489,33; воскресенье 14.06.2026 — 489,33; 1 января 2026 — 505,53; Наурыз 22.03.2026 — 482,33. Пустого ответа фид на нерабочий день не отдаёт. Значение на выходной совпадает с курсом ближайшего следующего рабочего дня — это следствие правила «курс применяется со следующего рабочего дня после торгов», то есть Нацбанк переносит курс сам, на своей стороне.

Что из этого следует. Курс на дату берётся напрямую, без домысливания. **Механизм поиска назад с флагом `carriedForward` в клиенте оставляем** — но только как техническую страховку на сбой фида и очень старые даты. *(Исправлено 19.08.2026: прежняя редакция ссылалась на «п. 5 ст. 190», якобы обязывающую применять последний определённый курс. Такой нормы в кодексе нет — ст. 190 о взыскании задолженности физического лица. Правила курса исчерпываются ст. 21 пп. 3): официальный курс, установленный Национальным Банком. Правила переноса с предшествующего рабочего дня новый кодекс не содержит.)* Но в интерфейсе он не должен создавать шум: пометка «перенос с такой-то даты» показывается **только когда перенос действительно был**, строка «перенесено: 0» из сводки убирается.

**3. Из браузера напрямую нельзя.** Сайт НБ РК не отдаёт заголовки CORS. Загрузка идёт через бэкенд.

**4. Опубликованный курс за прошедшую дату не меняется.** Кэшируйте навсегда, без TTL. Квартал — это девяносто с лишним запросов, и повторять их при каждом открытии страницы незачем.

## Что реализовать

### Серверная часть

Бэкенд Allkey на Python и FastAPI, поэтому берите **`nbrk_rates.py`** — порт под ваш стек. Разбор XML на stdlib, сеть на httpx (он уже есть в стеке FastAPI через TestClient). Асинхронный, как остальной бэкенд. Версия на Node (`nbrk-rates.js`) остаётся как справочная — если понадобится тот же загрузчик в desktop-приложении AI-BUH.

Класс `NbrkRates`, методы:

| Метод | Назначение |
|---|---|
| `get_day(day)` | Все валюты на дату. `None`, если публикации не было |
| `get_latest()` | Последние опубликованные курсы |
| `get_official_rate(code, day)` | **Главный метод для помогайки.** Курс с переносом с предыдущего рабочего дня. Возвращает `OfficialRate` с полями `rate`, `requested_date`, `actual_date`, `carried_forward`, `name`, `quant` |
| `get_range(codes, start, end, fill_gaps, on_progress)` | Диапазон дат по списку валют, с заполнением пропусков |

Кэш подключается через конструктор — объект с асинхронными `get(key)` и `set(key, value)`. По умолчанию в памяти; **для продакшена нужна таблица в PostgreSQL**, ключ — дата, значение — список курсов. Курс за прошедшую дату неизменен, так что это самый простой кэш, какой бывает: пишем один раз, читаем всегда.

Важная деталь реализации кэша: `MemoryCache.get` возвращает `...` для «не знаем» и `None` для «знаем, что публикации не было». Если перепутать, каждое обращение к выходному дню будет заново дёргать НБ РК. В своей реализации сохраните это различие.

Параллелизм ограничен четырьмя запросами через семафор, есть повторы с экспоненциальной задержкой и таймаут пятнадцать секунд. Сбой на отдельной дате не валит весь диапазон.

Тесты — `test_nbrk_rates.py`, 22 проверки, сеть не нужна: `get_day` подменяется. Кладите в `backend/app/f10104/tests/` или в общий модуль и **не забудьте расширить `testpaths` в `pytest.ini`**.

### Эндпоинты

```
GET /api/rates?codes=USD,EUR&from=2026-06-01&to=2026-06-30
→ [{ date, code, name, rate, quant, carriedForward, sourceDate }]

GET /api/rates/official?code=USD&date=2026-06-15
→ { code, name, rate, quant, requestedDate, actualDate, carriedForward }
```

Второй эндпоинт вызывает помогайка. `codes=ALL` — все валюты. Ограничение периода — 400 дней.

### Интерфейс

Прототип `kursy-valyut.html` — рабочий референс поведения. Что в нём есть и должно остаться:

- поле ввода валют плюс чипы популярных для быстрого выбора;
- пресеты периодов: кварталы, текущий месяц, с начала года;
- таблица с колонкой **«изменение за день»** — знаковое значение `change` из фида НБ РК: рост, падение, без изменения. Именно это бухгалтер
  ищет глазами, сверяя регистр. Прежняя колонка «источник: публикация / перенос» отменена — после находки от 19.08.2026 она всегда
  показывала бы «публикация»;
- пометка **«перенос с такой-то даты»** — не колонка, а значок в строке, появляющийся только при `carriedForward: true`,
  такая строка визуально приглушена;
- сводка: строк, валют, дней; «перенесено N» — только при N больше нуля;
- выгрузка в CSV с разделителем «точка с запятой», десятичной запятой и BOM — чтобы Excel открывал по-русски без плясок с импортом;
- выгрузка в JSON и копирование в буфер.

**Для продакшена сделайте настоящий .xlsx**, а не CSV: шапка с периодом и валютами, закреплённая строка заголовков, числовой формат курса с нужным числом знаков, колонка «источник» с пометкой переноса, автоширина колонок. Файл идёт в подшивку к налоговому регистру, и его будут открывать через год — он должен читаться без пояснений.

Верстать в стиле существующих сверок, тёмную тему прототипа не копировать.

### Встраивание в помогайку 101.04 — поток «загрузили один раз, работаем весь квартал»

Логика такая: курсы тянутся **один раз в начале сессии**, а не по одному на каждую операцию.

**Шаг 1 — блок S1 (шапка).** Пользователь выбирает налоговый период и валюту расчётов. Как только выбрана валюта, отличная от тенге, показывается панель загрузки курсов:

- **период по умолчанию — квартал операции плюс месяц назад.** Не с начала года: месяца назад достаточно, чтобы покрыть предоплаты, начисленные в предыдущем квартале, а объём запросов к НБ РК вчетверо меньше. Для II квартала 2026 это 01.03 — 30.06;
- кнопка **«Расширить до начала года»** рядом — на случай, когда бухгалтер разбирает операции за несколько кварталов сразу;
- после загрузки — сводка: сколько строк, за сколько дней, за какой период, из НБ РК или из кэша.

**Шаг 2 — блок S4 (даты и суммы).** Курс подставляется автоматически по выбранной дате:

- под полем курса — статус: «Официальный курс НБ РК на 15.06.2026 — 531,89» либо предупреждение о переносе;
- кнопка **«Подтянуть с НБ РК»** для явной подстановки;
- если дата выходит за загруженный период — сообщение «расширьте период или введите вручную», без молчаливого подставления чего попало;
- ручной ввод остаётся всегда.

**Шаг 3 — выгрузка.** На экране результата и в модуле курсов — кнопка **«Выгрузить курсы за период»** в Excel. Это приложение к налоговому регистру: ст. 205 НК обязывает вести регистр, форма не утверждена, разрабатывается самостоятельно, и обоснование курса в нём лишним не будет.

**Чего делать не надо: не превращайте Excel в шаг потока.** Курсы должны падать в кэш системы, а не проходить через руки пользователя. Схема «скачай файл и загрузи его обратно» — шаг назад от того, что есть сейчас. Excel — это выгрузка для отчётности, а не способ передачи данных внутри продукта.

**Кэш общий на всю систему.** Курс за прошедшую дату не меняется никогда, поэтому первый пользователь, загрузивший квартал, оплачивает загрузку за всех: второму бухгалтеру тот же период отдастся мгновенно. Через пару недель работы кэш покроет весь год, и обращения к НБ РК станут единичными — только за свежие даты.

**Предзагрузка.** Когда помогайка открывается, можно фоном подтянуть текущий квартал по популярным валютам. К моменту, когда пользователь дойдёт до шага дат, курсы уже будут на месте.

### Детали по шагу дат

На шаге «Даты, суммы, курс» (блок S4 в ТЗ):

- рядом с полем курса — кнопка **«Подтянуть с НБ РК»**;
- курс подставляется по `/api/rates/official` на нужную дату;
- **три разные даты дают три разных курса** в одной операции: на дату выплаты для КПН по выплаченным доходам, на дату начисления при авансе, на дату совершения оборота для НДС. Тянуть нужно каждый отдельно, не переиспользуя один курс для всего;
- если курс перенесён с предыдущего рабочего дня — показать это явно: «официальный курс на 15.06.2026 не публиковался, применён курс от 13.06.2026»;
- ручной ввод оставить: бывают ситуации, когда бухгалтеру нужно поставить свой курс с обоснованием;
- подставленный курс и его источник сохранять в сессии прохождения вместе с ответами — для воспроизводимости расчёта.

## Тесты

Файл `test_nbrk_rates.py` — 22 проверки на pytest-совместимом стиле, сеть не требуется, все проходят. Node-версия `test-parser.js` — справочная. Обязательный минимум:

| Проверка | Ожидание |
|---|---|
| Разбор `get_rates.cfm` | Дата документа и список валют |
| Разбор `rates_all.xml` | Дата из `pubDate`, `change` со знаком |
| Нормализация по `quant` | Иена: сырое 292.00 при `quant=100` → **2.92** |
| Пустой ответ фида | Пустой список, не ошибка |
| Перенос курса *(искусственный случай)* | Подменённый фид без публикации → курс от предыдущего дня, `carriedForward: true`. На живом фиде эта ветка не срабатывает, тест держим на моке |
| Неизвестная валюта | `null`, а не выдуманное значение |
| Диапазон с пропусками | Четыре дня → четыре строки, пропуски помечены |
| CSV | Шапка плюс строки по числу записей |

Добавьте интеграционный тест с реальным запросом к НБ РК — один, за известную дату, с проверкой, что USD в разумных пределах. Пометьте его так, чтобы он не падал в CI при недоступности внешнего сайта.

## Чего не делать

- Не кэшировать `rates_all.xml` надолго — он меняется ежедневно, разумный TTL порядка часа.
- Не тянуть курсы синхронно при рендере страницы: квартал — это девяносто запросов, страница встанет. Загрузка асинхронная, с прогрессом.
- Не хранить сырой курс без `quant` и без нормализации — через полгода никто не вспомнит, что там было за число.
- Не выдумывать курс, если НБ РК его не публиковал. Либо перенос с явной пометкой, либо честное «нет данных».

## Замечание на будущее

Правила определения рыночного курса с 01.01.2026 изменились: доллар считается по средневзвешенному биржевому курсу на 15:30 по времени Астаны, прочие валюты — кросс-курсами через доллар на 16:00, и курс применяется со следующего рабочего дня после торгов. Фид НБ РК уже отдаёт результат с учётом этих правил, пересчитывать ничего не нужно. Но если появятся расхождения с тем, что видит бухгалтер в банке, причина скорее всего здесь — стоит держать в голове.
